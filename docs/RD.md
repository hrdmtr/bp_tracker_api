# 血圧記録アプリ 要件定義書（フェーズ1）

## 1. プロジェクト概要

### 1.1 アプリ名
血圧記録帳（仮）

### 1.2 目的
- 血圧計の画面を撮影するだけで簡単に測定値を記録
- 環境データ（天気・気温・気圧）と合わせて保存
- 個人の体質・特性と血圧の関係を探るためのデータ収集
- **プライバシーファースト設計**: データは端末内で完全に管理

### 1.3 背景
- 現在、降圧剤を服用中で医師の指導のもと定期的に血圧測定を実施
- 統計的な一般論ではなく、個人の特性に基づいた血圧管理を目指す
- 既存の血圧計（ネット連携非対応）をそのまま活用したい
- 手動での記録が面倒で継続が困難
- **健康データは機微情報であり、サーバーに保存したくない**

### 1.4 解決したい課題
- 血圧計の測定値を簡単に電子化したい
- 環境要因（天気、気温、気圧）と血圧の相関を分析したい
- 時刻と血圧の関係を把握したい
- **個人情報をサーバーに送信・保存せず、プライバシーを完全に保護したい**

## 3. 主要機能

### 3.1 血圧データの記録

#### 3.1.1 撮影フロー
1. **カメラ起動**
   - アプリ内から直接カメラを起動
   - 血圧計を撮影しやすいUIガイド表示（フレーム表示など）

2. **撮影**
   - シャッターボタンで撮影
   - 撮影した画像はアプリ内のみで処理
   - ギャラリーには保存しない

3. **画像認識（バックエンドAPI経由）**
   - バックエンドAPIに画像を送信
   - バックエンドがOpenAI APIを呼び出し（中継のみ）
   - 以下の情報を抽出：
     - 最高血圧（収縮期血圧）mmHg
     - 最低血圧（拡張期血圧）mmHg
     - 脈拍数 拍/分
     - 血圧計の機種名（型番）
   - **サーバー側でデータは保存されない**

4. **位置情報の取得と粗粒度化**
   - アプリが端末の位置情報を取得
   - 緯度経度を都市名に変換（クライアント側で）
   - プライバシー保護のため、詳細な位置情報は送信しない

5. **環境データの取得（バックエンドAPI経由）**
   - 都市名をバックエンドAPIに送信
   - バックエンドがOpenWeatherMap APIを呼び出し（中継のみ）
   - 以下の情報を取得：
     - 天気情報（晴れ、曇り、雨など）
     - 気温（℃）
     - 気圧（hPa）
     - 湿度（%）
   - **サーバー側でデータは保存されない**

6. **確認・編集画面**
   - 認識結果を表示
   - 誤認識の場合は手動で修正可能
   - 各項目を編集可能なフォーム
   - 「もう一度撮影」ボタン配置

7. **追加情報の入力（任意）**
   - メモ欄（体調、気になることなど）
   - 測定タイミング（起床後、就寝前、運動後など）※任意

8. **保存**
   - **すべてのデータをローカルデータベース（SQLite）に保存**
   - サーバーには一切保存されない
   - データの所有者は完全にユーザー

#### 3.1.2 血圧計機種の扱い
- 画像認識時に機種名を取得
- **ローカルDBに保存**（サーバーには送信しない）
- 記録画面では小さく表示
- 機種別の統計分析に活用可能

#### 3.1.3 環境データ取得失敗時の対応
- 天気情報が取得できない場合も血圧データは保存
- 環境データ取得ステータスを記録：
  - "success": データ取得成功
  - "failed": データ取得失敗
- 失敗時は値を未設定とする（nullは使用しない）

### 3.2 データの表示

#### 3.2.1 記録一覧画面
- 記録したデータをリスト表示
- 表示項目：
  - 測定日時
  - 最高血圧 / 最低血圧
  - 脈拍数
  - 天気アイコン、気温
- 新しい順に表示
- タップで詳細画面へ遷移

#### 3.2.2 詳細画面
- 選択した記録の全情報を表示：
  - 測定日時
  - 最高血圧、最低血圧、脈拍数
  - 機種名
  - 天気、気温、気圧
  - 環境データ取得ステータス
  - メモ
  - 測定タイミング
- 編集ボタン
- 削除ボタン

### 3.3 データの編集・削除

#### 3.3.1 編集機能
- 詳細画面から編集モードへ遷移
- すべての項目を編集可能
- 保存で更新

#### 3.3.2 削除機能
- 詳細画面から削除
- 確認ダイアログを表示
- 削除後は一覧画面へ戻る

## 4. データ項目

### 4.1 血圧記録データ

| 項目名 | データ型 | 必須 | 保存場所 | 説明 |
|--------|----------|------|----------|------|
| id | Integer | ○ | ローカル | 主キー（自動採番） |
| 測定日時 | DateTime | ○ | ローカル | 撮影時刻（後から修正可能） |
| 最高血圧 | Integer | ○ | ローカル | mmHg |
| 最低血圧 | Integer | ○ | ローカル | mmHg |
| 脈拍数 | Integer | ○ | ローカル | 拍/分 |
| 機種名 | String | - | ローカル | 血圧計の型番 |
| 環境データ取得ステータス | Enum | ○ | ローカル | success / failed |
| 天気 | String | - | ローカル | 晴れ、曇り、雨など |
| 天気コード | String | - | ローカル | clear, cloudy, rainなど |
| 気温 | Float | - | ローカル | ℃ |
| 気圧 | Float | - | ローカル | hPa |
| 湿度 | Integer | - | ローカル | % |
| 都市名 | String | - | ローカル | 札幌市、東京都など |
| 測定タイミング | String | - | ローカル | 起床後、就寝前など |
| メモ | Text | - | ローカル | 自由記述 |
| 作成日時 | DateTime | ○ | ローカル | レコード作成時刻 |
| 更新日時 | DateTime | ○ | ローカル | レコード更新時刻 |

**重要**: すべてのデータは端末内（ローカルDB）のみに保存され、サーバーには送信・保存されません。

### 4.2 ユーザー識別情報

| 項目名 | データ型 | 必須 | 保存場所 | 説明 |
|--------|----------|------|----------|------|
| user_uuid | String(36) | ○ | ローカル | アプリ生成のUUID（認証用） |

**特徴**:
- 初回起動時にアプリが自動生成
- API認証とレート制限に使用
- 個人を特定する情報は含まない
- サーバー側では匿名識別子として扱う

## 5. 技術仕様

### 5.1 開発環境
- **フレームワーク**: Flutter
- **開発ツール**: Claude Code
- **対象プラットフォーム**: iOS / Android

### 5.2 使用技術・API

#### 5.2.1 画像認識（バックエンドAPI経由）
- **バックエンドAPI**: 独自Webサービス（中継のみ）
- **LLM**: OpenAI API（gpt-4o または gpt-4o-mini）
- **機能**: 血圧計画像から数値と機種名を抽出
- **エンドポイント**: `POST /api/v1/record-measurement`
- **データフロー**:
  ```
  [アプリ] → [バックエンドAPI] → [OpenAI API]
                ↓
  [アプリ] ← [認識結果のみ返却]
  ```
- **重要**: バックエンドは中継のみ行い、データを保存しない

#### 5.2.2 天気情報取得（バックエンドAPI経由）
- **バックエンドAPI**: 独自Webサービス（中継のみ）
- **天気API**: OpenWeatherMap API
- **取得データ**: 天気、気温、気圧、湿度
- **エンドポイント**: `POST /api/v1/record-measurement`（統合API）
- **位置情報の扱い**:
  - アプリ側で緯度経度を取得
  - 都市名に変換（クライアント側）
  - サーバーには都市名のみ送信（プライバシー保護）
- **データフロー**:
  ```
  [アプリ] → [バックエンドAPI] → [OpenWeatherMap API]
                ↓
  [アプリ] ← [天気情報のみ返却]
  ```
- **重要**: バックエンドは中継のみ行い、データを保存しない

#### 5.2.3 位置情報
- **パッケージ**: Flutter geolocatorパッケージ
- **Geocoding**: Flutter geocodingパッケージ
- **取得方法**:
  1. 端末の位置情報（緯度経度）を取得
  2. Geocodingで都市名に変換
  3. 都市名のみをサーバーに送信
- **権限**: 位置情報アクセス許可が必要（任意、拒否時も動作可能）
- **プライバシー**: 詳細な位置情報はサーバーに送信しない

#### 5.2.4 データベース

**フェーズ1（MVP - 現在）**:
- **ローカルストレージ**: SQLite（sqfliteパッケージ）
- **保存場所**: 端末内のみ
- **保存データ**: 
  - 血圧測定値
  - 血圧計機種情報
  - 環境データ（天気、気温、気圧）
  - 測定日時、メモなど
  - ユーザーUUID
- **特徴**:
  - オフラインで完全に動作
  - データの所有者はユーザー
  - 開発者はアクセス不可

**フェーズ2以降（検討中）**:
- **クラウド委譲方式**: Google Drive / iCloud
- **目的**: 
  - 機種変更時のデータ引き継ぎ
  - 複数デバイス間の同期
  - 自動バックアップ
- **方針**:
  - データはユーザーのクラウドストレージに保存
  - 開発者は引き続きデータにアクセス不可
  - ユーザーが完全にデータを管理

#### 5.2.5 カメラ
- **パッケージ**: Flutter cameraパッケージ
- **権限**: カメラアクセス許可が必要

#### 5.2.6 認証（段階的実装）

**フェーズ1（MVP - 現在）**:
- **UUID認証**: ソフト認証方式
- **生成方法**: アプリ初回起動時にUUIDv4を生成
- **保存**: ローカルストレージ（SharedPreferences）
- **用途**: API認証とレート制限
- **特徴**: 
  - 事前登録不要
  - 任意のUUIDを受け付ける
  - ユーザー登録・ログイン不要

**フェーズ2（将来）**:
- ブラックリスト機能追加
- 不正利用UUIDを永久ブロック

**フェーズ3（将来）**:
- UUID事前登録制（ホワイトリスト）
- 機種変更時の引き継ぎ機能
- 詳細は「バックエンドAPI仕様書」参照

### 5.3 権限
アプリが必要とする権限：
- **カメラアクセス**（必須）
- **位置情報アクセス**（任意、拒否時は環境データなしで動作）
- **インターネットアクセス**（必須、API通信用）

## 7. セキュリティとプライバシー

### 7.1 基本方針
このアプリは「**プライバシーファースト**」の設計思想に基づいています。

**中核原則**:
- データの所有者は完全にユーザー
- サーバーに個人情報を保存しない
- ユーザーが自分のデータを完全に管理

### 7.2 データの保存場所と管理

#### 7.2.1 サーバー側（バックエンドAPI）
- **保存するデータ**: なし
- **役割**: 外部API（OpenAI、OpenWeatherMap）への代理リクエストのみ
- **処理フロー**:
  1. クライアントからリクエスト受信
  2. 外部APIを呼び出し
  3. 結果をクライアントに返却
  4. **即座にデータを破棄**
- **保存期間**: リクエスト処理中のみメモリに保持

#### 7.2.2 クライアント側（端末）
- **保存するデータ**: すべての測定データ
  - 血圧測定値（要配慮個人情報）
  - 血圧計機種情報
  - 環境データ（天気、気温、気圧、都市名）
  - 測定日時
  - メモ
  - ユーザーUUID
- **保存場所**: SQLiteローカルデータベース
- **アクセス権限**: ユーザーのみ
- **管理者**: ユーザー本人
- **削除**: ユーザーがいつでも削除可能

#### 7.2.3 将来的なクラウド保存（フェーズ2以降）
- **保存場所**: ユーザーのGoogle Drive または iCloud
- **管理者**: ユーザー本人
- **開発者のアクセス**: 不可能
- **削除権限**: ユーザーがいつでも削除可能
- **方針**: データ管理をクラウドサービスに委譲

### 7.3 個人情報の取り扱い

#### 7.3.1 取得する情報
- **血圧測定値**（要配慮個人情報）
- **位置情報**（都市名レベルに粗粒度化）
- **血圧計機種情報**
- **ユーザーUUID**（匿名識別子）

#### 7.3.2 サーバーへの送信
- **画像**:
  - 認識処理のため一時的に送信
  - 処理後、即座にメモリから削除
  - ディスクに保存しない
  
- **位置情報**:
  - 詳細な緯度経度は送信しない
  - 都市名のみ送信（プライバシー保護）
  - 例: "43.0642, 141.3469" → "札幌市"
  
- **認識結果**:
  - 血圧値、機種名は保存せず、クライアントに返却のみ
  
- **ユーザーUUID**:
  - APIリクエストの認証用ヘッダーとして送信
  - レート制限の識別に使用
  - 個人を特定する情報は含まない

#### 7.3.3 サーバーログ
- **記録する情報**:
  - タイムスタンプ
  - エンドポイント
  - HTTPステータスコード
  - ユーザーUUID（匿名識別子）
  
- **記録しない情報**:
  - 血圧測定値
  - 血圧計機種名
  - 都市名・位置情報
  - その他の個人を特定できる情報
  
- **保持期間**: 30日（トラブルシューティング用）

#### 7.3.4 第三者への提供
- **一切行いません**
- 統計情報の公開も行いません
- 外部APIプロバイダー（OpenAI、OpenWeatherMap）への送信のみ
  - これらは認識・天気取得の処理に必要不可欠
  - 各社のプライバシーポリシーに準拠

### 7.4 ユーザーの権利

#### 7.4.1 データの所有権
- すべてのデータの所有権は完全にユーザーに帰属
- 開発者はユーザーのデータにアクセス不可

#### 7.4.2 削除権
- ユーザーはいつでもアプリ内からデータを削除可能
- アプリをアンインストールすることで完全にデータ削除

#### 7.4.3 エクスポート権
- データのエクスポート機能を提供（将来実装）
- CSV形式などでエクスポート可能

#### 7.4.4 同意の撤回
- アプリをアンインストールすることで同意を撤回
- サーバーにデータがないため、追加の削除依頼は不要

### 7.5 セキュリティ対策

#### 7.5.1 通信セキュリティ
- すべてのAPI通信はHTTPS（TLS 1.2以上）
- 中間者攻撃の防止
- APIキーはサーバー側で管理（クライアントに露出しない）

#### 7.5.2 データ保護
- **ローカルDB**: 端末のセキュリティ機能で保護
  - iOS: Data Protection API（自動）
  - Android: アプリ専用ストレージ（他アプリからアクセス不可）
- **暗号化**: 将来的にDB暗号化を検討（フェーズ2以降）

#### 7.5.3 認証とアクセス制御
- UUID認証によるレート制限
- 異常なアクセスパターンの検知と一時ブロック
- 詳細は「バックエンドAPI仕様書」参照

### 7.6 準拠法規

#### 7.6.1 日本
- **個人情報保護法**: サーバーに個人情報を保有しないため、管理義務なし
- **要配慮個人情報**: 血圧データは端末内のみで管理

#### 7.6.2 国際
- **GDPR**（EU）: 将来的に海外展開する場合も、データ保存なしでコンプライアンス負担軽減
- データ主体の権利（削除、エクスポート等）への対応が容易

### 7.7 透明性の確保

#### 7.7.1 ユーザーへの説明
アプリ内で以下を明示：

```
【データの取り扱いについて】

✓ あなたの血圧データは、あなたの端末内にのみ保存されます
✓ サーバーには一時的に送信されますが、保存されません
✓ 開発者はあなたのデータにアクセスできません
✓ データの所有者は完全にあなたです

【外部サービスの利用】
画像認識と天気情報の取得のため、以下のサービスを利用します：
- OpenAI API（画像認識）
- OpenWeatherMap API（天気情報）

これらのサービスへの送信は処理に必要な最小限の情報のみで、
あなたの個人を特定する情報は含まれません。
```

#### 7.7.2 プライバシーポリシー
- アプリ内で閲覧可能
- データの流れを図解
- わかりやすい言葉で説明

### 7.8 セキュリティインシデント対応

万が一、セキュリティインシデントが発生した場合：

1. **調査**: 影響範囲の特定
2. **対応**: 脆弱性の修正
3. **通知**: ユーザーへの影響がある場合は通知
4. **報告**: 法令に基づく報告（該当する場合）

**重要**: サーバーにデータを保存しないため、データ漏洩のリスクは極めて低い標
- LLM API呼び出し：5秒以内のレスポンスを想定

### 7.2 ユーザビリティ
- 毎日続けられるシンプルなUI
- 最小限の操作ステップ
- 誤入力の防止と修正の容易さ

### 7.3 セキュリティ
- データはローカル保存のみ（外部送信なし、API通信は暗号化）
- 画像は処理後即座に破棄

### 7.4 エラーハンドリング
- ネットワークエラー時の適切なメッセージ表示
- LLM認識失敗時の再撮影フロー
- 環境データ取得失敗時も記録可能
